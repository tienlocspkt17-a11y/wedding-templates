# QA report: cinematic intro rework

Checked after the final build:

- 10 standalone HTML files are generated with no framework or app dependency.
- The output no longer includes the old `opening-stage`, `opening-trigger`, `opening-reveal`, panel, veil or mechanism markup/CSS.
- Every file has one `intro-cinematic--<mode>` scene, one scene-specific art structure and one real, centered action button: 68px on desktop and 72px on mobile.
- Concepts 03 (Geometric Camera) and 09 (Astrolabe Promise) retain their approved scene markup and choreography; the overhaul is scoped to the other eight modes.
- The runtime starts the page fade at 2.64s and completes the opening sequence at 3.0s. Reduced motion presents the final readable state without a forced three-second wait.
- While the intro dialog is active, the main invitation is marked `inert` and `aria-hidden`; the handoff removes both attributes when the guest opens or skips the scene, so keyboard focus cannot drift into the page behind the intro.
- Every file retains all 17 configurable modules, plus editable intro action, prompt, kicker and reveal copy in `#wedding-config`.
- The validation script parses every inline script, verifies CSS brace balance, validates the JSON schema and confirms each module appears exactly once.
- Intro markup diversity is 10/10. The current validator reports the closest intro CSS pair as Message to Shore / Seoul Rain at 9% selector fingerprint overlap and the closest post-intro pair as Quiet Crossing / Message to Shore at 7%.
- The final intro CSS owns its own mobile safe zones. The action anchor sits at the visual centre in every concept; its editable cue is directly below it, the context stays in a top reading band, and final title layouts collapse to a readable centre alignment below 760px. The fixed journey bar reserves bottom space so it cannot cover the final module.
- The final body polish gives each concept its own `--ui-*` text/surface token set. Primary body text, muted copy, strong-surface text, accent labels and form fields were contrast-audited; all audited text pairs are at least 4.5:1. Mobile event cards, gallery tiles, FAQ rows, form controls and the fixed journey navigation were re-spaced for thumb reach and safe-area clearance.
- The body rework adds a four-unit countdown tied to `content.dateISO`, a generated responsive calendar with a heart marker on the configured wedding date, and an `.ics` export using the configured event times and city. The invitation letter now has metadata, a seal, quote hierarchy and signature treatment instead of a plain bordered paragraph.
- Guestbook QA covers a seeded auto-sliding carousel with previous/next/pause controls, `aria-live` viewport semantics, safe `textContent` insertion for new wishes, and an explicit pause while the carousel is hovered or focused so a guest never loses their place while reading. The pause control exposes `aria-pressed`, and reduced motion disables autoplay/slide transitions. All 10 templates receive their own guestbook surface and countdown/calendar skin.
- Every body module receives a scroll reveal observer with a no-observer fallback and a `prefers-reduced-motion` path; the first module is explicitly revealed when the 3-second intro completes so the transition never leaves a blank hero.
- A CSS hardening pass isolates the decorative hero ornament from copy/button stacking and moves each ornament into a safe mobile position. Body reveal motion is no longer one shared animation: the validator requires and finds 10 mode-specific body keyframes (silk wipe, botanical settle, focus lock, washi fold, pigment bloom, tide rise, stepped film, shadow stage, astrolabe orbit and rain clear).
- Responsive audit covers desktop grid constraints and mobile collapse rules: all split-grid children are `min-width: 0`, editable names wrap, mobile journey navigation reserves safe-area space, touch targets remain at least 44px, decorative ornaments move below/away from hero copy, and the Washi vertical writing mode cannot leak into its countdown/calendar controls.
- A final cascade repair adds explicit high-specificity mobile resets for art-directed grids: Invitation sections collapse to one column, event cards stack with their map action in-flow, four-column galleries become a readable two-up album, the guestbook carousel and form become one vertical flow, and gift-card actions cannot create an implicit third column.
- The same breakpoint now forces every art-directed hero/story split to a single track and caps photo widths at the content box; a broad `overflow: hidden` fallback protects embedded webviews that do not support `overflow: clip`.
- A 900px narrow-layout fail-safe now catches visual-viewport scaling edge cases: Washi switches from vertical writing to horizontal text, every hero/story/invitation/video/dress split is forced to one track, event cards and galleries collapse safely, and photo widths are capped before names can collapse into a one-character column.
- Typography loads Vietnamese subsets plus Noto/Be Vietnam fallback families so names, addresses and RSVP copy remain legible even when a concept display font lacks Vietnamese glyphs.
- Intro motion is one-shot and tied to a specific action: prism/ring alignment, cyanotype contact print, focus lock, origami folding, wax-resist marbling, tide-pool reflection, fixed-gate Super 8 transport, giấy dó registration under a projection beam, orbital conjunction and a metro light clearing rain glass. The Super 8 validator additionally confirms that the gate remains centred while `.super8-film-track` is the element that transports.

The collection remains a standalone preview set. It does not integrate into EverAfter or any app.
